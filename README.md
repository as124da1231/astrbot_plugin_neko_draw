# 猫娘画图

![猫娘画图](./logo.png)

一款以 **APNG 制作与双帧展示**为特色的 AstrBot 多提供商图片生成与编辑插件，当前版本 **4.0.3**。

预设可搜索、筛选和启停；停用后保留内容但不触发。所有文字加工编辑统一使用右下角保存，
文字加工会话隔离按扩写、提取分别设置全局开关，每条指令还可跟随全局或单独强制开启/关闭。
收起与切换会提示保留到草稿。生图模型选择仅显示明确启用的生图配置，没有编辑模型时显示空状态。

文字加工经有状态反代时，在「文字加工配置 → 扩写/提取 · 模型、超时与独立会话」里打开对应开关即可，
每次扩写、提取和预处理都会附带一次性的独立 `user` 标识；不需要填写提供商 ID，
也不会修改共享提供商配置或影响普通聊天、其他模型与提示词格式。
不需要某条指令参与隔离时，在该指令卡片里把「独立会话」设为「强制关闭」。

图片生成完成后，插件可以先快速展示猫娘首帧，再揭晓生成结果，并把两帧合成为一张 APNG 动图。内置首帧就是上图，也可以在 WebUI 中上传自己的图片替换。也可以直接把 QQ 消息里的多张图片合成为 APNG。

支持 WaveSpeed、RunningHub（含 ComfyUI 工作流）、兼容 OpenAI Images Generations 格式的服务，以及 AstrBot 中已经配置的提供商，并提供模型管理、预设提示词、生成历史、白名单、限流和独立 WebUI 控制台。

> 本 README 只说明**当前版本怎么用**。历史版本改了什么见 [CHANGELOG.md](CHANGELOG.md)，代码分层见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 安装

插件标识为 `astrbot_plugin_neko_draw`。

可以通过 AstrBot 插件管理页面上传插件压缩包，或将插件目录放入：

```text
AstrBot/data/plugins/
```

安装后在插件管理页启用或重载「猫娘画图」。插件已发布到 AstrBot 插件市场，也可以直接从市场安装。

## 五分钟上手

1. **安装并重载**插件。
2. 打开插件 WebUI → **模型提供商** → 新增一个提供商，填 `API Base URL` 与 `API Key`，点「获取模型列表」后勾选要用的模型。RunningHub 不提供模型搜索，用「自定义模型」手填 ID。
3. 到 **生图设置** 的「默认模型选择」里，给「默认文生图模型」「默认图片编辑模型」各选一个。选“无”表示该类不回退到任何模型。
4. 群里发送 `nd 一只白猫在窗台上晒太阳`。带图或回复图片时，同一句会自动走图片编辑。
5. 想看效果或排查问题，打开 **生成历史**，每条都能看到用户原话、实际提示词、参数和耗时。

只做 APNG、不画图的话，第 2～3 步可以跳过，直接发 `apng` 加多张图。

## WebUI 五个页面

侧边栏从上到下五个入口，互不重叠：

| 页面 | 用途 |
| --- | --- |
| 模型提供商 | 管理 API 凭据、图片模型、ComfyUI 工作流；测试连接与余额 |
| 插件配置 | 默认模型、预设提示词、ComfyUI 工作流、生图设置、APNG 设置、限流与白名单、网络 |
| 生成历史 | 模型生成的图片：筛选、详情、下载、找回 / 补发 |
| APNG 作品 | `apng` 指令的输入原图记录（成品不留存） |
| 文字加工 | 扩写 / 提取两种纯文字指令的配置、编辑与调用历史 |

**文字加工**里有四页，名字固定：**文字加工配置**、**扩写指令编辑**、**提取指令编辑**、**文字加工历史**。点指令小卡片（只显示唤醒词）即整行就地展开；没单独指定提供商和模型的指令，按「文字加工配置」的设置走。

页面右侧两个圆角图标按钮分别是「重新加载」和「保存并重载」。主题可在右上角静默切换（森林实验室 / 奶油画室 / 午夜霓虹），只影响当前这次打开。手机端是抽屉式导航，历史记录会变成纵向卡片。

## QQ 指令总表

所有指令**带不带 @ 都能用**：`nd 一只猫`、`@铃 nd 一只猫` 都行（会自动剥掉开头的 @）。

### 画图与动画

| 指令 | 说明 |
| --- | --- |
| `nd <提示词>` | 生成图片；消息包含参考图或回复了图片时自动走图片编辑 |
| `nde <提示词>` | 强制走默认图片编辑模型 |
| `apng [间隔秒数] [循环次数] [--fd 首帧秒数]` | 把随消息发送 / 回复 / 合并转发里的图片合成 APNG；省略间隔用 WebUI 默认值 |
| `--model <模板名>` | 临时指定模型模板 |
| `--参数名 <值>` | 覆盖模板参数或增加新参数 |

示例：

```text
nd 黄昏海边，海浪拍打礁石，电影感写实摄影 --aspect_ratio 16:9 --resolution 2k
nde 把图片中的人物改成赛博朋克风格
nd 像素风角色 --model rh_seedream_lite
apng 4 3 --fd 1.5
```

图片编辑需要随消息发图，或回复一条含图的消息。

最终请求参数按「内置推荐值 → 当前模型保存值 → 预设固定参数 → 预设模板里的 `--参数` → QQ 消息里的 `--参数`」合并，后者覆盖前者。参数值会做基础类型转换：

- `true`、`false` 转换为布尔值
- 数字文本转换为数字
- 只写名字不带值，视为 `true`
- 其他内容保留为文本

### 管理员指令 `/nc`

| 指令 | 说明 |
| --- | --- |
| `/nc h` | 查看完整字母缩写帮助 |
| `/nc pa <触发词> <提示词>` | 添加或更新预设 |
| `/nc pd <触发词>` | 删除预设 |
| `/nc pl` | 列出预设触发词 |
| `/nc ps <触发词>` | 查看预设详情 |
| `/nc ea` / `/nc ed` / `/nc el` | 扩写指令的添加 / 删除 / 列表 |
| `/nc ta` / `/nc td` / `/nc tl` | 提取形象指令的添加 / 删除 / 列表 |
| `/nc wa <u或g> <ID>` | 添加用户（u）或群组（g）白名单 |
| `/nc wd <u或g> <ID>` | 删除用户或群组白名单 |
| `/nc wl` | 查看白名单 |
| `/nc fs` + 图片 | 用随消息发送的、或回复的那张图设置 APNG 首帧 |

触发词写错时（例如 `/nc pd 不存在的词`），回复会直接列出**当前有哪些**可用触发词。预设、白名单、扩写 / 提取这三类管理指令都仅限 AstrBot 管理员，非管理员不会有任何回应。

## 模型提供商与默认模型

「模型提供商」是与「生成历史」并列的独立页面，不占用插件配置区域。页面左右分栏：左侧选择或新增提供商，右侧直接编辑连接、高级配置和模型列表。

插件提供商只管理插件自己的 URL 与 Key，不会混入 AstrBot 提供商设置，也不需要手动选协议。以硅基流动为例：填 `https://api.siliconflow.cn/v1` 和 API Key，点「获取模型列表」；搜索框同时过滤已配置模型和待添加模型。只有点「自定义模型」时才允许手工填写模型 ID。选好模型后可继续设置用途（文生图 / 图片编辑）、显示名称、参考图字段、回退优先级和请求参数。

插件按 URL 自动识别 WaveSpeed、RunningHub 或 OpenAI 兼容协议；无法识别的地址按 OpenAI 兼容处理。只有地址里明确含 `wavespeed` 时才会把模型 ID 拼进请求路径。WaveSpeed 不提供通用模型搜索，需通过「自定义模型」填写；RunningHub 走自己的任务提交和轮询流程。

「默认模型选择」与提供商配置分离，包含「默认文生图模型」和「默认图片编辑模型」两个下拉框，都可以选“无”；选“无”时对应类型不会自动回退到其他模型。下拉框同时列出插件内已启用的对应用途模型和 AstrBot 当前已启用的模型。保存后模型客户端立即刷新，不需要重启插件。

### 新增提供商

| 字段 | 说明 |
| --- | --- |
| 提供商 ID | 插件内唯一的连接名称 |
| API Key | 该提供商使用的访问密钥 |
| API Base URL | 接口根地址；填写后自动识别调用协议 |
| 超时时间、代理、自定义请求头 | 只作用于当前提供商 |

可以添加多个提供商（官方接口、兼容中转、备用账号等）。连接测试不会提交图片生成任务。

首次安装时模型提供商和默认模型均为空，不会自动建立 WaveSpeed、RunningHub 或 OpenAI 项，请按实际使用的服务自行新增；升级用户原来保存的提供商与模型会继续迁移和保留。

AstrBot 已有模型不会混进这个页面，只会出现在「默认模型选择」的候选项里；聊天模型不一定支持图片生成，选择前仍需确认端点能力。

> API Key 属于敏感信息，请勿截图、公开或提交到代码仓库。

## 内置模型

| 模型提供商 | 用途 | 内置模型 |
| --- | --- | --- |
| WaveSpeed 文生图 | 使用 WaveSpeed API 生成图片 | `bytedance/seedream-v5.0-pro` |
| WaveSpeed 图片编辑 | 使用 WaveSpeed API 编辑参考图 | `bytedance/seedream-v5.0-pro/edit` |
| RunningHub 文生图 | 使用 RunningHub API 生成图片 | `seedream-v5-lite/text-to-image` |
| RunningHub 图片编辑 | 使用 RunningHub API 编辑参考图 | `dola-Seedream-5.0-pro/image-to-image` |
| OpenAI | 调用兼容 Images Generations 格式的接口 | `gpt-image-2` |

首次升级时，原有模型会跟随对应提供商迁入同一张卡片。模型名称、用途、参考图字段和请求参数均可在 WebUI 中修改。

> OpenAI 兼容模型调用图片生成接口。兼容服务需要支持 Bearer Token 和 JSON 请求；插件可读取 `data[].url`、`data[].b64_json` 以及 SiliconFlow 使用的 `images[].url` 响应。不同服务的实际兼容程度可能不同。

## 图片模型

每个模型代表一套可以独立调用的图片生成配置，直接归属于当前提供商。WebUI 会根据模型 ID 和提供商地址显示推荐参数，但不会自动写入；只有主动点「添加推荐参数」才会补充尚未设置的字段，已有人工参数不会被覆盖。所有参数都可自由增删改。

| 字段 | 说明 |
| --- | --- |
| 显示名称 | 供默认模型和 `--model` 参数引用，必须全局唯一 |
| 模型 ID | 从服务商返回列表选择；仅自定义模型可手工填写 |
| 模型用途 | 文生图或图片编辑 |
| 启用模型 | 控制模型是否可用 |
| 允许作为默认模型 | 控制模型是否参与默认模型选择 |
| 默认回退优先级 | 指定模板不存在、被停用或不适合当前模式时生效；数字越小优先级越高 |
| 参考图字段名 | 编辑模型使用的请求字段；文生图留空 |
| 参考图数量上限 | 单次请求允许使用的参考图数量 |
| 提示词最小长度 | 提交前的提示词长度限制 |
| 请求参数 | 发送给模型接口的附加参数 |

提供商 ID、模型显示名称和预设触发词都必须唯一。不同模型接受的参数可能不同，请以对应提供商当前的接口文档为准。

### ComfyUI 工作流

RunningHub 工作流的 API JSON 可在「模型提供商」页面直接上传解析，映射出提示词、尺寸、采样步数等可调字段，也可以把被下游连线引用的常量节点（CR Text、StringContains、MathExpression 等）识别为「常量文本」，直接改值。同一个工作流里有多个常量文本节点时，下拉里用「节点号 · 标题」区分。

**三种调用方式**（每个工作流条目单独选）：

| 模式 | 走什么接口 | 需要什么 |
|---|---|---|
| 工作流接口 | `/run/workflow/{id}` | 平台上已保存的工作流 ID |
| AI 应用接口 | `/run/ai-app/{appId}` | 应用 ID（`/ai-detail/` 页面取） |
| 原生代理 | `/proxy/{KEY}/prompt` | 只需上传过整份 API JSON，不用 ID |

原生代理直接把整份 JSON 提交给平台，因此可以带任意节点结构、增删连线、换模型；代价是改动**不落盘**成新的工作流，下次不重新上传就回到原样，适合临时实验。

**上传过的 JSON 可以下载回来**：每个条目右侧有下载按钮，取回该条目当前使用的 `_api.json`，不用再回平台导出。升级前建的老条目没有保存过原始 JSON，按钮是灰的，重新上传一次即可补齐。

**更新 API 不会清空映射**：重新上传同一个工作流的新版本时，插件按「节点 ID + 字段名 + 节点类型」把旧用途搬过来，并提示「沿用 N 项 / 新增 N 项 / 移除 N 项」。值一律以新 JSON 为准（模型名、LoRA 文件名这类更新要能生效），用途沿用你的设置。如果新旧字段重合率低于 30%，说明换了一份工作流，会重建映射并提示重新确认。

工作流上的「测试」按钮**不会真正生成图片、不消耗额度**：它只校验工作流 ID（原生代理模式改为校验已保存的 JSON）、运行模式、参数映射是否齐全，以及 RunningHub 地址与 Key 是否可用。工作流是否「已保存并运行过一次」必须真正跑一次才知道，这个测试不做。

## 预设提示词

预设可以在 WebUI 中添加和修改，也可以用 `/nc pa` 等管理员指令维护。预设内容可以使用 `{{user_text}}`，调用时替换为用户输入。预设还可以配置固定参考图，并决定它位于用户图片之前或之后。

旧版「在提示词模板里写 `--参数 值`」的用法仍然可用。

### 在 WebUI 里能设什么

- **默认模型**：从已配置模型中选一个「触发此预设时使用的模型」（插件内模型 / ComfyUI 工作流 / AstrBot 已有模型皆可）。留空则跟随全局默认模型。
- **固定参数**：选好模型后，面板会**从该模型调取可调参数**逐个添加，不用盲写 `--参数 值`。
  - ComfyUI 工作流：列出「参数映射」里的全部用途（如 `steps / cfg / width / height / lora_strength / artist_style`），带中文名称和对应输入控件。
  - 普通模型：列出该模型「自定义请求参数」的键。
  - 也可「自定义参数」手写任意键。
- **优先级**：预设固定参数 < 预设模板里的 `--参数` < 用户消息里的 `--参数`。用户随时可用 QQ 消息里的 `--参数 值` 覆盖预设设置。
- **APNG 包装**：控制触发此预设时是否把生成图包装成两帧 APNG。「跟随生图设置」用全局开关；「转成 APNG」强制包装；「普通图片」强制不包装。
- **生图预处理**：控制触发此预设时是否先用「扩写」把用户原话处理成提示词。「跟随全局」用总开关；也可强制「预处理」或「不预处理」。
- **预处理用哪条扩写**：下拉选择「文字加工 → 扩写指令编辑」里的触发词；留空用第一条启用的。

## 出图预处理（扩写）

出图前可以把用户原话先交给「文字加工 → 扩写」处理成完整提示词，再提交给画图模型。这样中文口语也能稳定出图。

**默认关闭**。3.9.2 升级时会统一关闭一次（迁移），之后由你自己决定。

| 配置 | 位置 | 说明 |
| --- | --- | --- |
| 默认启用生图预处理（扩写） | 文字加工配置 | 总开关。预设选「跟随全局」时用它 |
| 预处理失败时回退原文本 | 文字加工配置 | 开启时失败直接用原话绘图；关闭则回复失败提示、不消耗绘图额度 |
| 生图预处理 | 预设提示词（每条预设） | 跟随全局 / 预处理 / 不预处理 |
| 预处理用哪条扩写 | 预设提示词（每条预设） | 下拉选择「扩写指令编辑」里的触发词；留空用第一条启用的 |

**用哪条扩写、用什么模型、超时多少，全部跟着那条扩写指令走**（在「文字加工 → 扩写指令编辑 / 文字加工配置」里设置），不再有第二套配置。

预处理只在通过限流、即将真正生成前调用。想先看处理结果又不想出图，直接发「扩写 xxx」——它和预处理用的是同一份模板，只是不发图。

预处理的结果会写进「文字加工历史」，来源标记为「生图预处理」，可以和用户自己发的「扩写」分开筛选。

## 文字加工：扩写与提取

两条**只回文字、不出图**的指令，在 WebUI 侧边栏「文字加工」里维护，分四页：「文字加工配置」放全局模型与超时，「扩写指令编辑」「提取指令编辑」各自维护触发词和提示词，「文字加工历史」记录每次调用。它们和绘图预设完全分开存储，互不干扰。

这里的「扩写」同时也是出图预处理的来源，见上一节。

指令前带 @ 也能识别（例如 `@铃 提取`）。

- **扩写**：发送「触发词 + 简短描述」，对话模型把一句话扩成完整提示词。
- **提取**：发送「触发词 + 图片」，对话模型读出可复现的形象特征；也可以回复一张图，或 @ 一个人用他的头像。

| 全局配置 | 说明 |
| --- | --- |
| 扩写 / 提取的模型提供商、模型、超时 | 条目没单独指定时使用；指定了提供商就忽略条目里残留的模型名，避免把别家的模型名套上去 |
| 开始提示 | 收到指令先发一句（如「正在扩写提示词，请稍候…」），让用户知道模型已在处理 |
| 结束提示 | 追加在结果后面的一句说明，留空则不追加 |
| 回复时 @ 发送者 | 开启后回复前带上发送者的 @ |
| 取图顺序 | 本条消息图 → 引用图 → 合并转发图 → @ 头像，按配置从左到右尝试，取到即停；去掉某一项即禁用该来源。用浮块管理：点下方未启用的项加到最右边，点浮块上的 × 取消 |
| 排序方式 | `buttons`：用浮块上的 ← → 按钮调整先后（默认）；`drag`：按住浮块直接拖动。二选一，× 取消两种方式下都能用 |

没取到图时，提示只说**当前真正可用的**取图方式；关掉「提取形象时支持 @ 头像」后，就不会再让你去 @ 人。

每次调用都会写入独立的调用历史（与绘图历史分开的 `llm_history.db`），在「文字加工历史」页查看：调用类型、来源、触发词、输入输出、提供商与模型、耗时、成功或失败及原因。来源分「用户指令」和「生图预处理」，可以单独筛选。可在全局配置里设置保留条数（默认 500，0 表示不限制）。列表每行有「复制结果」，详情页有「复制生成结果」，复制到的都是纯文本提示词。

### 指令需要自己添加

本版本**不内置任何扩写 / 提取指令**，首次安装时两个分区都是空的，请在
「文字加工 → 扩写指令编辑 / 提取指令编辑」里按需要自己添加（或让管理员用 `/nc ea`、`/nc ta` 添加）。

写指令时记住两条约定：
- **系统提示词**放规则（要求模型怎么思考、输出什么格式）；
- **提示词模板**只放用户内容：扩写用 `用户描述：{{user_text}}`，提取留空（靠图片，用户补充的说明会接在末尾）。

## 多图制作 APNG

发送 `apng` 并在同一条消息中附带多张图片，插件会按消息顺序合成 APNG；没有填写间隔时使用 WebUI 的默认值 5 秒。也可以发 `apng 4`，`4` 表示首帧以外的每帧停留 4 秒，首帧使用 WebUI 设置的默认时长。

```text
apng
apng 4
apng 4 3
apng 4 --fd 1.5
```

- `apng 4 3`：其余帧 4 秒、播放 3 次；循环次数为 `0` 时无限循环。
- `apng 4 --fd 1.5`：本次首帧 1.5 秒；省略 `--fd` 用 WebUI 的默认首帧时长。

取图来源：本条消息图片、回复消息中的图片、图片文件，以及 QQ 合并转发聊天记录中的图片。

参数写错时会点名是哪一项、范围是多少：

| 现象 | 回复 |
| --- | --- |
| `apng 0.05` | 间隔需 0.1～60 秒 |
| `apng abc` | 「每帧间隔“abc”不是有效数字」 |
| `apng 4 --fd` | `--fd` 后面缺少秒数 |
| 只发了 1 张、默认最低 2 张 | 「只收到 1 张，最少 2 张，再补 1 张就能开始制作」 |

默认最低 2 张、最多 20 帧、最大画布边长 2048 像素，都可在 WebUI 修改。最低图片数设为 1 时，只带一张图片会自动在前面补入当前默认首帧；首帧可以是内置图片，也可以通过 WebUI 或 `/nc fs` 设置。不同尺寸的图片会等比缩放、居中，并用白色补齐，不会裁剪。

一批图里个别下载失败时，只报告失败的那几张，其余照常合入。你自己重复发的同一张图会被保留，只有补充解析器多带的副本会被丢掉。

QQ 合并转发取图依赖 OneBot v11 协议端的 `get_forward_msg` 接口，适用于 aiocqhttp + NapCat 等支持该接口的环境。其他平台或不支持该接口的协议端仍可用普通消息图片制作 APNG。

## APNG 双帧展示

开启 APNG 包装后的处理顺序：

```text
生成图片 → 猫娘首帧 → 生成结果 → APNG 动图 → 发送
```

WebUI 提供两套完全独立的发送设置：

- **生图设置**：控制模型生图的生成中提示、排队补发提示、外显金句、合并转发、@ 触发者和双帧首帧包装。
- **APNG 设置**：控制 `apng` 指令成品的外显金句、合并转发、@ 触发者、默认首帧、动画参数、历史上限和完全无痕清理。

两套设置各有自己的金句列表、金句文件、转发昵称和默认首帧，互相不会覆盖。APNG 包装失败时会改发原图，成品不会凭空空掉；发送失败也不会留下一条空历史。

生图默认设置：

| 设置 | 默认值 |
| --- | --- |
| 开始生成时发送提示 | 开启 |
| 排队超时转后台补发提示 | 开启，`小猫还在排队等出图，出来马上补发原图/ᐠ - ˕ -マ Ⳋ` |
| 生图外显金句 | 关闭 |
| 生图合并转发 | 关闭 |
| 发送生图时 @ 触发者 | 关闭 |
| 生图首帧包装 | 关闭 |
| 生图默认首帧 | 插件内置猫娘图片 |
| 生图首帧 / 结果帧时长 | `100 ms` / `20000 ms` |
| 生图包装循环 / 压缩 | 无限循环 / 开启 |

APNG 默认设置：

| 设置 | 默认值 |
| --- | --- |
| APNG 制作时发送提示 | 开启，`小猫正在搓屏幕中/ᐠ - ˕ -マ Ⳋ📱` |
| APNG 外显金句 | 关闭 |
| APNG 合并转发 | 关闭 |
| 发送 APNG 时 @ 触发者 | 关闭 |
| APNG 默认首帧 | 插件内置猫娘图片 |
| 未指定 `--fd` 时的首帧时长 | `100 ms` |
| 未指定间隔时的默认间隔 | `5 秒` |
| 默认循环次数 | `0`，无限循环 |
| 压缩优化 | 开启 |
| 指令制作最大帧数 | `20` |
| 指令制作最低图片数 | `2` |
| 指令制作最大边长 | `2048 px` |
| APNG 完全无痕清理 | 关闭 |
| APNG 历史保存上限 | `200` 条 |

APNG 三态（跟随全局 / 转成 APNG / 普通图片）统一按「结果上的值 → 预设里的值」一条规则决定。任一首帧未上传自定义图片时，都会独立回退到内置 `default_apng_frame.png`。

## 输出设置

猫娘画图支持普通图片消息、@ 触发者、APNG 动图包装、图片外显文案和 QQ 合并转发消息。

APNG 默认关闭；开启后使用内置猫娘首帧，也可以上传自定义首帧。第一帧、第二帧停留时间、循环次数和压缩优化均可独立设置。管理员也可以直接在 QQ 里管理首帧和包装开关（见[管理员指令 `/nc`](#管理员指令-nc)）。

图片外显和合并转发依赖 `aiocqhttp` 平台。其他平台不支持时会自动回退为普通图片。多图外显会自动回退普通图片。

## 白名单与限流

### 白名单

白名单默认关闭。启用后，只有指定用户或群组可以使用绘图功能。

| 指令 | 说明 |
| --- | --- |
| `/nc wa <u或g> <ID>` | 添加用户（u）或群组（g）白名单 |
| `/nc wd <u或g> <ID>` | 删除用户（u）或群组（g）白名单 |
| `/nc wl` | 查看白名单 |

参数写错时会说清是类型错还是 ID 错；加进白名单但总开关没开，回复会提醒一句。白名单和预设管理命令仅限 AstrBot 管理员。

### 限流

支持单用户多时间窗口限流、限流白名单、最大并发任务数、WaveSpeed 429 指数退避重试、请求代理、轮询间隔和任务超时。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用单用户限流 | 关闭 | 可配置多个规则同时生效，任一超限即触发 |
| 限流规则 | 300 秒内 3 次 + 每日 10 次 | 可添加多条，各自独立检查 |
| 最大并发任务数 | `2` | 超出时自动排队等待，而不是直接报错 |
| 任务超时 | `600` 秒 | 超时后**转入后台继续等待**，出图自动补发 |
| 轮询间隔 | `2` 秒 | RunningHub 等异步任务的查询间隔 |
| 代理地址 | 空 | 如 `http://127.0.0.1:7890` |

任务超时内没跑完时，插件不会直接判失败，而是转入后台继续等待，出图后自动补发原图，并把任务 ID 记入历史与日志，方便追溯。不同账户和服务套餐的并发额度可能不同，请按提供商控制台显示的实际额度设置最大并发数。

## 生成历史

生成历史会记录**用户原始消息**与**实际发给模型的提示词**，以及本次生效的选项（是否预处理、预处理结果、APNG 包装取值与最终是否包装）。开启预处理后，可以在详情里直接对照「用户原话 → 预处理结果 → 实际提示词」。

每一条都记录成功和失败：用户、群组、提示词、模板、提供商、模型、请求参数、参考图数量、生成耗时、状态和错误信息。RunningHub 任务还会额外记下**任务 ID** 与**来源会话**。

成功生成的多张图片和本次使用的多张输入原图都可以在详情中查看、逐张下载。列表和详情先加载缩略图，点击后才读取完整原图。支持筛选、分页、单条删除、全部清空和保存上限（默认 200 条，0 表示不保留）。

**查历史**：顶部一个关键词框同时搜「提示词 / 最终提示词 / 触发词 / 模型模板 / 模型 ID / 任务 ID / 用户 ID / 失败原因」；另有用户 ID、模型模板、状态、起止日期四个精确条件，以及「最新优先 / 最早优先 / 耗时从长到短 / 耗时从短到长」四种排序。想快速看某段时间，点「今天 / 近 7 天 / 近 30 天」即可。

**三种排列方式**：「生成记录」面板右上角可在 **列表 / 一行 4 个 / 一行 6 个** 之间切换。后两种是缩略图墙，卡片上直接显示封面、状态、提示词、耗时和时间，点卡片进详情；窗口变窄时会自动降为 3 / 2 / 1 列。选择记在浏览器本地，下次打开保持。

**找回 / 补发**：凡是记录了任务 ID 的记录，操作列都会显示找回按钮。点一下即用该任务 ID 到 RunningHub 取回成品图，写回这条历史（缩略图随即可见、状态转为成功），并把原图**补发到当初生成它的会话**。适合处理「图已生成但没成功发到群里」的情况。平台按 API Key 隔离任务，插件会自动在全部 RunningHub 提供商的全部 Key 上依次查询；平台查不到（仍在排队、已被清理或非本插件提交）时会给明确提示。

图片编辑任务会把实际提交给模型的原图复制到插件数据目录。删除记录、清空历史或超出上限时，该记录的数据库信息、输入原图、生成图和全部缩略图都会一起删除。开启「生图完全无痕清理」后，本次请求不会留下记录或插件托管文件。

## APNG 文件与清理

`apng` 指令制作的动画成品只用于本次发送，发送完成后始终从服务器删除。独立的「APNG 作品」页面只保存并展示制作时的输入原图副本，支持多图缩略图、按需查看原图、逐条删除和全部清空。

开启「APNG 完全无痕清理」后，插件还会跳过历史写入，不保留输入原图副本或缩略图。生图也有独立的完全无痕开关。两类历史可分别设置保存上限，超出的最旧记录会连同全部插件托管文件一起删除；设为 0 表示不保留对应历史。

生图首帧包装产生的临时 APNG 只负责本次发送，发送完成即清理；生成历史保留包装前的原始生成图。

## 环境要求

- AstrBot `4.24.1` 或更高版本
- 用 AI 画图需要至少一组可用的提供商 API 凭据；只制作 APNG 不需要
- 外显金句和合并转发依赖 `aiocqhttp`（如 NapCat）；不支持时自动回退普通图片
- QQ 合并转发取图依赖 OneBot v11 的 `get_forward_msg` 接口

## 数据存储与升级

生成图片、历史记录、预设提示词和白名单保存在 AstrBot 分配的插件数据目录中。更新插件时不应删除该目录；卸载或清理数据前，请先备份需要保留的内容。

配置键名、`plugin_data` 数据文件路径和指令名在升级时**保持不变**，直接覆盖或上传新压缩包即可。旧版的「模型提供商 + 模型模板」配置会在首次启动时自动合并迁移；旧版插件类上的方法名也仍然可用（转发到新模块）。

## 常见问题

**发了指令没反应？**
- 画图 / APNG 需要先在 WebUI 里配好提供商与默认模型；去「生成历史」看有没有失败记录和具体原因。
- 扩写 / 提取看「文字加工配置」里的模型是否可用。
- `/nc` 管理指令只对管理员生效，非管理员不会有回应。

**`apng` 说图片不够？**
最少张数默认 2，回复会直接告诉你还差几张。也可以把「APNG 制作最低图片数」设成 1，插件会自动在前面补一张默认首帧。

**`apng 0.05` 为什么报错？**
每帧间隔最低 0.1 秒（100 毫秒），上限 60 秒。

**图生成了但没发到群里？**
去「生成历史」点该记录的找回按钮：用任务 ID 取回成品、写回历史，并补发到当初的会话。旧记录没有来源会话信息时只取回、不补发。

**APNG 手机上看不动 / 只显示一帧？**
QQ 手机端通常把 APNG 持续循环，可能忽略文件里设置的有限循环次数；部分客户端只显示其中一帧，属正常表现。

**工作流「测试」会花钱吗？**
不会。它只校验工作流 ID、运行模式、参数映射是否齐全，以及 RunningHub 地址与 Key 是否可用，**不提交生图任务、不消耗额度**。

**改了配置要重启吗？**
大部分不用，保存后立即生效；「取图顺序」「排序方式」等少数项需要重载插件（页面右侧的「重新加载」按钮）。

## 注意事项

- 图片生成可能产生第三方 API 费用
- 模型名称、参数、价格和可用性可能由提供商随时调整
- RunningHub 不同模型接口使用的参数名称可能不同
- 文生图模板收到图片时会忽略参考图
- 编辑模板没有收到参考图时会提示用户补充图片
- 参考图会在提交前转换为提供商支持的 URL 或 Data URI
- 请确保生成内容符合所使用平台的服务条款和当地法律法规
